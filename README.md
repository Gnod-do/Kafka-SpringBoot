# Kafka Spring Lab

A simple Spring Boot lab project that demonstrates a **Kafka producer + consumer flow** with practical reliability patterns:

- Producer publishes `OrderCreatedEvent` messages to Kafka.
- Consumer reads messages manually and commits offsets only after successful processing.
- Consumer uses an H2-backed idempotency table to skip duplicate event processing.

This repository is useful as a reference for learning **at-least-once delivery**, **manual acknowledgment**, and **idempotent consumers** in Spring Kafka.

## Architecture overview

This project runs one Spring Boot application with two runtime profiles:

- `producer` profile (default port `8080`): exposes REST API to publish order-created events.
- `consumer` profile (default port `8081`): consumes events from Kafka and stores processed event IDs in H2.

### Event flow

1. Client calls `POST /orders` on producer.
2. Producer creates an `eventId` (UUID) and sends an `OrderCreatedEvent` to topic `order.created`.
3. Consumer receives the event from Kafka.
4. Consumer checks `ProcessedEventRepository`:
   - If `eventId` already exists => skip and ack.
   - Else => process, persist `eventId`, then ack.
5. If an exception happens before ack, message is redelivered (at-least-once).

## Environment & configuration

Main configuration lives in `src/main/resources/application.yml`:

- Kafka bootstrap server: `localhost:9092`
- Topic name: `order.created`
- Producer:
  - `acks=all`
  - `enable.idempotence=true`
- Consumer:
  - `group-id=notification-service`
  - `enable-auto-commit=false`
  - `auto-offset-reset=earliest`
  - manual ack via custom `KafkaListenerContainerFactory`
- Profiles:
  - `producer` -> server port `8080`
  - `consumer` -> server port `8081`

## Setup

### 1) Start Kafka infrastructure

```bash
docker compose up -d
```

### 2) Create the topic (required)

Auto topic creation is disabled in `docker-compose.yml`, so create topic `order.created` explicitly:

```bash
docker exec -it $(docker ps --filter "ancestor=confluentinc/cp-kafka:7.6.0" -q | head -n 1) \
  kafka-topics --bootstrap-server localhost:9092 \
  --create --topic order.created --partitions 3 --replication-factor 1
```

To verify:

```bash
docker exec -it $(docker ps --filter "ancestor=confluentinc/cp-kafka:7.6.0" -q | head -n 1) \
  kafka-topics --bootstrap-server localhost:9092 --describe --topic order.created
```

### 3) Build the project

```bash
mvn clean package
```

### 4) Run producer and consumer

Run in two separate terminals:

```bash
mvn spring-boot:run -Dspring-boot.run.profiles=producer
```

```bash
mvn spring-boot:run -Dspring-boot.run.profiles=consumer
```

## How to test

### A) Unit/integration tests from Maven

```bash
mvn test
```

### B) Manual end-to-end functional test

1. Start Kafka + producer + consumer as above.
2. Publish an order event:

```bash
curl -X POST http://localhost:8080/orders \
  -H "Content-Type: application/json" \
  -d '{
    "orderId": "ORD-1001",
    "userId": "USER-01",
    "totalAmount": 159900
  }'
```

Expected producer response: HTTP `202 Accepted`.

3. Check consumer logs; you should see a line like:

```text
[PROCESS] partition=... offset=... key=ORD-1001 eventId=... orderId=ORD-1001 total=159900
```

4. Send another request with same order payload (new eventId is generated by producer). It should process again as a new event.

5. (Optional) To validate duplicate handling, re-publish the exact same Kafka message/eventId using a custom producer script; the consumer should log `[SKIP] duplicate eventId=...`.

## Troubleshooting

- **No message consumed**:
  - Ensure topic `order.created` exists.
  - Ensure producer and consumer use same `bootstrap-servers` and topic name.
- **Consumer restarts on error**:
  - Expected if processing throws before `ack.acknowledge()`.
- **Port already in use**:
  - Change ports in `application.yml` profile blocks.
- **Kafka not reachable**:
  - Recheck Docker containers and mapped port `9092`.
